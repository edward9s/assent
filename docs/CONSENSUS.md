# AI 專案記憶管理：共識摘要

> 三輪討論（Claude Fable × GPT-5.6）的最終共識版本。
> 目標：在「正確實作」與「極致節省 tokens」之間取得最穩健的平衡。

## 核心思想

不是讓 AI 聰明地從幾千行中挑出相關內容，而是把上下文分層，
讓每次任務只需載入「足以無歧義開工的最小上下文」。

```text
永久規則   → AGENTS.md（root，工具自動載入的入口）
目前狀態   → .agents/CURRENT.md
本次任務   → .agents/tasks/ACTIVE.md
歷史證據   → .agents/logs/（分卷，預設不讀）
正確性證明 → scripts/verify.sh
```

## 四條核心原則

1. **分層**
   規則、現況、任務、歷史四者不混檔。
   每次開工只讀：AGENTS + CURRENT + ACTIVE + 直接相關程式碼。

2. **快取而非權威**
   CURRENT.md 是導航快照，不是事實來源。
   事實優先序：程式行為與測試結果 → 原始碼與 Git → ACTIVE → CURRENT → 日誌。
   CURRENT 記錄最後驗證的 commit hash；commit 已前進時先核對再信任。
   摘要與程式碼衝突 → 信程式碼，修摘要。

3. **重寫而非追加**
   狀態檔每次結束時重寫成現在式，過時內容刪除。
   過程細節進日誌（append-only、按月分卷）；被推翻的決策進 ADR。
   引用用標題錨點或穩定識別碼，不用會位移的行號。
   任務檔「執行上自包含」（目標、範圍、驗收、下一步直接寫），
   但共用知識引用而非複製，避免版本分歧。

4. **測試證明正確**
   文字說明意圖，測試證明正確。
   完成條件 = verify.sh exit 0 + 驗收條件逐項核對，不靠長篇叮嚀。
   摘要只寫可驗證事實，明確區分：已修改 / 已驗證 / 未驗證 / 已知失敗 / 推測。
   程式寫好 ≠ 任務完成；pending 不得包裝成 completed。

## 位置慣例

- `AGENTS.md` 必須留在 project root——agent 工具自動在 root 尋找指令檔，
  位置本身就是功能。它變薄，只做「規則 + 路由」。
- 其餘 AI 工作檔收進 `.agents/`，root 保持乾淨。
- `verify.sh` 留在 `scripts/`——它驗證專案正確性，非 AI 專屬，CI 也會用。

## 品質標準（取代 token 數字 KPI）

**冷啟動測試**：一個零記憶的新 AI 只讀必讀集，能否不問問題就正確說出
目標、限制、現狀、驗收條件？
能 → 工作集夠小；要讀幾千行才行 → 分層失敗。

token 預算（AGENTS 300–800、CURRENT 300–700、ACTIVE 500–1,500）
僅為參考值，不是硬指標。

這套架構消除的是「每次重讀全部歷史」的 O(n) 成長，
實際任務成本仍取決於需要檢查的程式碼與驗證輸出。

## 維護紀律

- AI 交接最容易在 session 尾聲、上下文快滿時鬆掉 → AGENTS 內建 Completion protocol 強制執行。
- 人工定期抽查「當前真相層」：CURRENT 是否對應現在的 commit、
  有無推測被寫成事實、有無被否決方案仍列為現行方案。
  失真的權威快照比沒有快照更危險。

## 升級路徑（先有痛點，再加結構）

| 痛點 | 才加入 |
|------|--------|
| 同一決策反覆被推翻、AI 重採已否決方案 | `.agents/decisions/`（ADR） |
| 多任務重複大量架構說明 | `.agents/architecture/` |
| 長期路線圖與短期狀態更新頻率差異過大 | 拆出 PLAN.md |

不要為可能永遠不會出現的問題，預先建立文件官僚體系。

## 一句話定案

> 用 AGENTS 管規則、CURRENT 管現在、ACTIVE 管本次、LOG 管歷史、
> verify.sh 管真假；預設只讀前三者，結束時驗證、重寫狀態、細節歸檔。
>
> 文件負責讓 AI 快速接手，Git 和測試負責保證事實，
> 人工負責防止快照失真——三者缺一，省下的 tokens 都會以返工的形式加倍還回去。
